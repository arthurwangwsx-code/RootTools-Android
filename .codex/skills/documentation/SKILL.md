# RootTools Documentation

1. Locate the canonical document from `docs/README.md` before adding a new file.
2. Use `docs/templates/` for research plans, feature designs, ADRs, and validation reports.
3. Keep facts, device observations, decisions, and future work distinguishable.
4. Architecture documents describe contracts and dependency direction, not transient implementation trivia.
5. Delivery ledger entries must include status, evidence, validation, and remaining risk.
6. Link new canonical documents from `docs/README.md`.

Do not create a second roadmap, second architecture file, or duplicate feature specification for convenience.
